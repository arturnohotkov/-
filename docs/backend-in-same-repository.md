# Спільний сервер у цьому самому GitHub-репозиторії

Проєкт залишається у **https://github.com/arturnohotkov/-**. Новий репозиторій і спроби ChatGPT Sites не потрібні.

## Що додано

- `cloudflare/worker.mjs` — HTTP API із чинного `core/live.mjs` (анкети, плани, статуси, роль керівника).
- `cloudflare/migrations/0001_workspaces.sql` — таблиця для збереження поточного стану з контролем ревізій, без видалення даних.
- `wrangler.jsonc` — конфігурація Cloudflare Workers із базою D1.
- `.github/workflows/backend-cloudflare.yml` — окремий ручний запуск розгортання цього самого коду через GitHub Actions.
- `offline/build-pages.mjs` — вибір серверного HTTPS API через GitHub Actions variable `VECTOR_API_URL`. Без цього налаштування зберігається початкова адреса сервера.
- Основний кабінет керівника зберігає локальний план та безпечно переносить його на авторизований сервер, коли той підтвердить підтримку власних заходів.

## Кроки, потрібні для запуску

Для запуску потрібен обліковий запис Cloudflare та створена в його розділі **D1 SQL Database** база з назвою `vorobtsi-integrity`. Знайдіть ідентифікатор `Database ID` на сторінці цієї бази. Далі додайте такі **GitHub Actions secrets** у цьому самому репозиторії:

1. `CLOUDFLARE_API_TOKEN` — токен із правами розгортання Workers, налаштування секретів та D1.
2. `CLOUDFLARE_ACCOUNT_ID` — ідентифікатор облікового запису Cloudflare.
3. `CLOUDFLARE_D1_DATABASE_ID` — ідентифікатор створеної бази D1 у форматі UUID (копіюється з Cloudflare).
4. `VECTOR_MANAGER_HASH` — SHA-256 **чинного** приватного ключа керівника (64 hex-символи). Сам приватний ключ нікуди не публікувати.

Відкрийте **GitHub → Settings → Secrets and variables → Actions → New repository secret**. Введіть ці чотири секрети. Не надсилайте мені сам ключ чи токен у чаті.

Після цього у **GitHub → Actions** виберіть **«Розгортання спільного API (Cloudflare)» → Run workflow**.
Процес:
- запускає тести;
- підключає вже створену D1 за її ідентифікатором і розгортає Worker;
- створює таблиці, не знищуючи вже наявні;
- додає приватний секрет керівника.

Перевірте `https://<назва-worker>.<ваш-workers-subdomain>.workers.dev/api/v1/live-info`: поле `manualMeasures` має бути `true`.

**Не перемикайте GitHub Pages на нову адресу без перевірки та перенесення наявних даних.** Новий D1 — окрема база, він не містить автоматично раніше зібраних анкет на ChatGPT Sites. Для точного збереження історії потрібен експорт вихідної бази з початкового Sites-проєкту й імпорт у новий D1 (або підключення до тієї самої D1, якщо доступ дозволяє). Спільна API-відповідь керівника не є повним експортом вихідної бази та не замінює його.

Лише після відновлення існуючої бази та перевірки логіну додайте GitHub Actions variable `VECTOR_API_URL` з HTTPS origin нового Worker (без кінцевого слеша). Публічна сторінка при наступній збірці почне звертатися до нього. Локально збережені заходи залишаться в браузері і автоматично перенесуться після входу керівника.

## Правила збереження даних

- **Не** очищайте localStorage браузера, де створювалися заходи, до успішної синхронізації.
- **Не** змінюйте `VECTOR_MANAGER_HASH` на хеш іншого ключа, якщо хочете зберегти чинний ключ входу.
- **Не** кладіть анонімні відповіді та ключі в публічні файли GitHub.
- Не створюйте новий проєкт ChatGPT Sites: новий API бере вихідний код із того самого GitHub-репозиторію.
- Демоверсія не змінюється й не використовує спільну базу.

У цьому GitHub-репозиторії тепер є **весь код для серверного розгортання**, але до підключення Cloudflare, секретів і даних початкового сервера синхронізація між пристроями на опублікованому сайті не активна.
