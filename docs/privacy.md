# Анонімність, етика і межі прототипу

Увесь демонстраційний набір синтетичний. Анкета не запитує прізвища, контакти, звання, підрозділи малого розміру або вільний опис подій. Вона призначена для оцінки роботи системи. Для фактичних звернень установа використовує свої офіційні канали.

## Як захищено основне опитування

На основному сайті учасники відповідають без прізвищ, контактів і відомостей про підрозділи. Застосунок видає браузерний квиток і не дозволяє повторно зарахувати анкету з тим самим квитком. Це **не є повноцінною перевіркою унікальності особи**: інший пристрій або новий браузерний профіль можуть отримати інший квиток.

Замість окремих анкет у спільному стані накопичуються кількості та суми відповідей за категоріями й запитаннями. Груповий бал відкривається лише після накопичення чергових **7 змістовних відповідей** на відповідне запитання. За окремою згодою учасник може передати підтримку запропонованого заходу без імені чи індивідуального бала. Тестові анкети, використані для перевірки роботи панелі, є синтетичними.

**Далі наведено запобіжники окремої навчальної демомоделі**, у якій діють власні цикли, одноразові запрошення та розмежування ролей. Їх не слід автоматично переносити на публічний збір.

## Що відбувається з відповіддю

Одноразовий випадковий код видається на цикл і категорію. Код передається учаснику у фрагменті URL. Браузер прибирає фрагмент з адреси після відкриття. Сервер зберігає геш невикористаного коду та його призначення. Після валідного надсилання однією операцією збільшуються групові суми, кількості прийнятих та змістовних відповідей, запис коду видаляється. Індивідуального рядка анкети в моделі даних немає. Паралельні оновлення узгоджуються за ревізією. Друге використання коду відхиляється. У журналі фіксуються адміністративні дії з роллю й датою. Застосунок не записує до журналу IP-адреси чи час проходження анкети.

## Можливі зловживання

| Ситуація | Реалізований запобіжник | Залишкове обмеження |
|---|---|---|
| Ідентифікація малої групи | Серверний поріг для кожного питання в групі, типово 7, мінімум 5. Приховані групи не впливають на видимі середні. Та сама логіка в CSV, API й інтерфейсі | Поріг не усуває ризику знання відповідей від інших учасників |
| Порівняння результату до й після окремої відповіді | Бали відображаються після одноразового закриття, архів зафіксовано. Під час збору видно охоплення лише на рівні груп | Адміністратори інфраструктури повинні обмежити доступ до резервних копій і проміжних версій бази |
| Повторне голосування | Одноразове запрошення, атомарне погашення й оновлення агрегатів | Особа, що роздає багато кодів, може зловживати видачею. Для реального застосування потрібен окремий контроль розподілу без прив’язки до анкет |
| Прикрашання самооцінки | Порівняння двох категорій, експертного й документального джерел. Внесення та підтвердження здійснюють різні ролі | Інституційне підтвердження саме по собі не засвідчує незалежного аудиту |
| Покарання посадовця за індекс | Одиницею оцінки є система установи, відсутні персональні рейтинги, за кожним сигналом потрібен розгляд | Порядок інтерпретації та використання звітів закріплюється політикою установи |
| Формальне закриття заходу | Статус виконання та зміна показника у наступному циклі відображаються окремо | Зміна показника не доводить причинності |
| Загальний доступ до адміністративних функцій | Для демонстрації окремі простори з ролями. Для автономного режиму установи — окремі ключі, перевірки ролей на сервері, заборона демонстраційного перемикання | Перед роботою з реальними даними потрібні відомчий IdP, індивідуальні облікові записи адміністративних ролей, ротація ключів, HTTPS, обмеження запитів і незалежна перевірка |

Сервер застосунку не може контролювати журнали проксі, хостингу, мережі або розсилання запрошень. У реальному пілоті власник інфраструктури має окремо перевірити налаштування журналювання, резервування, строки видалення та організаційну незалежність опитування.


У відкритому демо кожен відвідувач має власний простір із синтетичним набором. Для спільного опитування один уповноважений видає учасникам індивідуальні запрошення до свого циклу. Кнопка нового демоприкладу створює окремий простір для повторної демонстрації та дозволяє повернутися до попереднього. Додаткові питання зберігаються як кількість і сума балів за групою та питанням. Відповіді незавершеного опитування перебувають лише в оперативній пам’яті вкладки.

## Спільний збір

На головній сторінці та за адресою /survey відповіді з усіх пристроїв надходять до одного збору. Загальний лічильник не містить даних про категорію чи конкретну людину. Для кожної категорії й запитання сервер накопичує лише суми та кількості. Публічний для керівника зріз змінюється після чергових семи змістовних відповідей на питання в категорії. Відповідь «Не можу оцінити» враховується в участі й пропускається в розрахунках. Рекомендовану дію учасник бачить перед надсиланням. За окремою згодою до спільного лічильника для цієї пропозиції додається одна підтримка. Імена, відповіді та зв’язок між пропозицією, квитком і категорією не записуються. Квиток запобігає повторному врахуванню після перезавантаження або збою мережі в тому самому браузері. Власник спільного збору має зберігати ключ керівника окремо від матеріалів для учасників.
