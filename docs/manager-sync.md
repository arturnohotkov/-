# Спільне збереження заходів у кабінеті керівника

## Поточний стан

Основний кабінет на GitHub Pages — це інтерфейс. Спільна база та API розташовані на
`https://vektor-integrity-lab.clayblade5.chatgpt.site`.

Із попередньої версії кабінету залишилися локальні записи в `localStorage` за ключем
`vektor-manager-actions-v1:<base>:<backend>`. Вони **не є синхронізованими**.
Не видаляйте дані сайту з браузера до перенесення цих записів.

На GitHub уже реалізовано:
- серверний прийом довільних заходів із текстом, критерієм виконання, підрозділом і строком у `core/live.mjs`;
- збереження у спільному стані `shared-survey-v1` та оновлення статусу через `live-plan` і `live-status`;
- автоматичне перенесення локальних записів при вході керівника, якщо сервер повідомляє `manualMeasures: true`;
- повторну перевірку можливості синхронізації в кабінеті та кнопку **«Перевірити можливість синхронізації / Синхронізувати зараз»**;
- перевірку повного тексту, ознаки виконання, відповідального, строку і статусу після запису;
- збереження локального запису, якщо сервер недоступний, запис не підтверджено або виник конфлікт.

## Що необхідно для запуску на всіх пристроях

**Потрібно розгорнути оновлене ядро спільного сервера на існуючому хостингу**,
який обслуговує адресу `vektor-integrity-lab.clayblade5.chatgpt.site`.
Саме GitHub Pages не може виконувати запис у спільну БД.

1. У проєкті хостингу оновіть серверний обробник `handleLive` та його залежності
   до версії з `main/core/live.mjs`; збережіть маршрут `/api/v1/live-*`.
2. Збережіть **ту саму** базу D1/SQLite, прив'язку до неї, приватний ключ керівника і
   ключ простору `shared-survey-v1`. Нова порожня база призведе до втрати доступу
   до раніше зібраних анкет і заходів — так робити не можна.
3. Перевірте `GET /api/v1/live-info`. Відповідь має містити `"manualMeasures": true`.
4. Перевірте з авторизованого кабінету керівника: `POST /api/v1/live-plan` із полями
   `id, action, verify, owner, due` зберігає саме ці значення; `GET /api/v1/live-state`
   повертає захід, а `POST /api/v1/live-status` оновлює його стан.
5. На пристрої, де створювалися локальні заходи, увійдіть у кабінет керівника.
   Клієнт спробує перенести їх автоматично. За потреби натисніть **«Синхронізувати зараз»**.
6. Перевірте кабінет на іншому пристрої з тим самим ключем керівника:
   захід, підрозділ, строк і статус мають відображатися однаково.

Міграція **не видаляє локальну копію**, доки сервер не підтвердить збереження всіх полів.
Якщо на сервері вже є інший захід для тієї самої практики, застосунок показує
обидва тексти для ручного узгодження, не замінюючи спільні дані мовчки.

## Межі та безпека

- Доступ до синхронізації — через чинний ключ керівника й авторизовані запити.
  Не публікуйте ключ у GitHub або у фронтенд-коді.
- Демоверсія автономна та не використовує цей механізм.
- GitHub Pages і вихідний код на GitHub можуть бути оновлені без доступу до розгортання
  зовнішнього сервера. Саме серверне розгортання має виконати власник відповідного
  хостингу/проєкту.
